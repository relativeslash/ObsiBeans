# ObsiBeans contributing

## Shared standards and optional overrides

ObsiBeans inherits the global Protomatter standards through [[docs/Private/Contributing/Standards/README.md|the shared standards entry point]]. Follow its contextual-loading index and read only the standards relevant to the task.

`Standards/` is the shared standards mount, not a collection of ObsiBeans overrides. Direct local standards notes in this folder exist only to document actual differences from the shared defaults. Do not copy global rules or create empty per-topic standards notes merely to complete a template.

- A missing or empty local override note means the global standard applies unchanged. It is not a blocker and requires no exception or approval to proceed.
- Read applicable local overrides that do exist. An override identifies its scope, affected global rules, rationale, and any required approval/review trigger.
- Selecting a project option expressly permitted by a shared rule is configuration, not a waiver. Relaxing a mandatory shared rule still requires the shared standard's explicit human-approved exception process.
- Missing required shared standards or an explicitly required substantive project contract remain blockers for affected work. Optional override files are not such contracts.

## Local project information

Navigation and project facts are not duplicate standards. This README is the folder index; [[docs/Private/Contributing/ObsiBeans project info.md]] owns the compatibility baseline and future project-specific toolchain/profile declarations required by shared standards.

No additional substantive local standards overrides are declared at this update. An empty `Documentation standards.md`, if present, introduces no requirements and need not be populated without an actual override.
